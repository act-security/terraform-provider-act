# act_azure_onboarding_parameters (Data Source)

The values an Azure subscription or management group needs before it can connect to Act: the deployment ID, Act's app and service principal, the custom role to create and the roles to assign. A read, it creates nothing. For a target that already has a deployment, every value is the deployment's own.

## Example Usage

```terraform
data "act_azure_onboarding_parameters" "this" {
  directory_id    = "00000000-0000-0000-0000-000000000000"
  subscription_id = "11111111-1111-1111-1111-111111111111"
}

output "act_admin_consent_url" {
  value = data.act_azure_onboarding_parameters.this.admin_consent_url
}

output "act_custom_role_name" {
  value = data.act_azure_onboarding_parameters.this.custom_role_name
}
```

Pass `deployment_id` and `azure_tenant_id` to `act_azure_deployment`, and build the custom role and the role assignments from `custom_role_name`, `custom_role_actions`, `binding_marker`, `required_builtin_role_ids` and, for `include_entra_id`, `required_graph_app_role_ids`. The Act module for Azure, `act-security/act/azurerm`, does this for you. None of the values is a secret.

`tenant_consented` is false until an Entra admin of the directory approves Act by opening `admin_consent_url`. A deployment created before that is stored as `pending_consent`; the resource docs explain the approval. `act_service_principal_id` is null until Act's service principal exists in the directory.

When `existing_deployment` is set, the target already has a deployment, for example one created in the Act console. Import it rather than creating another; the `act_azure_deployment` docs show the `import` block, and creating another deployment fails with that block in the error.

## Schema

### Required

- `directory_id` (String) The Entra directory (Azure tenant) that owns the subscription or management group, a lowercase UUID.

### Optional

- `management_group_id` (String) The Azure management group to connect. Set this or `subscription_id`.
- `subscription_id` (String) The Azure subscription to connect, a lowercase UUID. Set this or `management_group_id`.
- `variant` (String) Set only for a second deployment over the same target: up to 32 lowercase letters, digits and hyphens.

### Read-Only

- `act_app_client_id` (String) The client ID of Act's multi-tenant app.
- `act_service_principal_id` (String) The object ID of Act's service principal in the directory. Null until an Entra admin approves Act, or until the service principal is created another way.
- `admin_consent_url` (String) The link an Entra admin opens once to approve Act in the directory. Reading it changes nothing; only opening it and approving does.
- `azure_tenant_id` (String) The Entra directory ID Act records for the target. Pass it to `azure_tenant_id` of `act_azure_deployment`.
- `binding_marker` (String) Text to put in the custom role's description. Act checks it to tie the role to this deployment. Not a secret.
- `custom_role_actions` (List of String) The actions of the custom role.
- `custom_role_name` (String) The name to give the custom role that holds the actions Act needs.
- `deployment_id` (String) The deployment ID Act issued for this target. Pass it to `deployment_id` of `act_azure_deployment`.
- `deployment_version` (String) The version the recommended module deploys. Null until Act publishes versioned modules and templates.
- `existing_deployment` (Attributes) The deployment that already covers this target, for example one created in the Act console. Null when there is none. Import it rather than creating another. (see [below for nested schema](#nestedatt--existing_deployment))
- `module_sha256` (String) The SHA-256 of the recommended module release. Null until Act publishes versioned modules and templates.
- `module_source` (String) The registry address of the Act module for Azure. Null until Act publishes versioned modules and templates.
- `module_version` (String) The module version Act recommends for this tenant. Null until Act publishes versioned modules and templates.
- `module_versions` (Attributes List) Every module version Act accepts today. Null until Act publishes versioned modules and templates. (see [below for nested schema](#nestedatt--module_versions))
- `permissions_hash` (String) A hash of the permissions the recommended module grants. Null until Act publishes versioned modules and templates.
- `required_builtin_role_ids` (List of String) The Azure built-in role definitions to assign to Act's service principal at the target, as role definition GUIDs.
- `required_graph_app_role_ids` (List of String) The Microsoft Graph app roles Act's service principal needs for `include_entra_id`, as app role GUIDs.
- `tenant_consented` (Boolean) Whether an Entra admin has already approved Act in this directory. While false, a new deployment is stored as `pending_consent`.
