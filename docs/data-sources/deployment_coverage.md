# act_deployment_coverage (Data Source)

How many of a deployment's accounts Act reaches right now. Use it in a `check` block: it changes as Act discovers and scans accounts, so the deployment resources never store it.

## Example Usage

```terraform
check "act_organization_coverage" {
  data "act_deployment_coverage" "this" {
    deployment_id = act_aws_organization_deployment.this.id
  }

  assert {
    condition     = data.act_deployment_coverage.this.accounts_failed == 0
    error_message = "Act cannot reach ${data.act_deployment_coverage.this.accounts_failed} accounts of the organization."
  }
}
```

A data source scoped to a `check` block only warns, so a member account Act cannot reach never blocks an apply. Right after a new organization deployment, `discovery_state` is `pending` or `running` and the counts are still growing.

## Schema

### Required

- `deployment_id` (String) The deployment ID.

### Read-Only

- `accounts_connected` (Number) Accounts Act reaches.
- `accounts_expected` (Number) Accounts Act expects to reach, excluded accounts left out.
- `accounts_failed` (Number) Accounts Act cannot reach.
- `accounts_pending` (Number) Accounts Act has not tried yet.
- `discovery_state` (String) `pending`, `running` or `complete`.
- `failed_accounts` (Attributes List) The accounts Act cannot reach. (see [below for nested schema](#nestedatt--failed_accounts))
- `last_discovery_at` (String) When Act last listed the accounts, in RFC 3339. Null before the first run.
