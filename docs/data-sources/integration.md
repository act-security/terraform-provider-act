# act_integration (Data Source)

An integration installed in the tenant, found by type or by ID. Use it to reference an integration Terraform does not manage, such as the Act-owned `email` integration or one installed in the Act console. Secrets are never returned.

The `email` integration is installed by Act for every tenant. Read it here to give a notification rule an email destination.

## Example Usage

```terraform
data "act_integration" "email" {
  type = "email"
}

output "email_integration_id" {
  value = data.act_integration.email.id
}
```

## Schema

### Optional

- `id` (String) The integration ID. Set this or `type`.
- `type` (String) The integration type: `slack`, `jira`, `wiz`, `splunk` or `email`. A tenant has at most one integration per type. Set this or `id`.

### Read-Only

- `config` (Map of String) The integration's settings that are not secret, keyed by their API names, such as `baseUrl`.
- `display_name` (String) The name Act shows for the integration.
- `health_note` (String) What to do about an unhealthy connection.
- `health_reason` (String) Why the connection is unhealthy, when Act reports a reason.
- `status` (String) The connection status: `connected`, `pending`, `error` or `disconnected`.
