# act_aws_account_deployment (Resource)

Connects one AWS account to Act through an IAM role in that account. Act verifies the role before it stores anything, so the apply fails and nothing is created when Act cannot use it.

## Example Usage

Read the onboarding values first, create the role from them, then connect the account:

```terraform
data "act_aws_onboarding_parameters" "this" {
  account_id = "111111111111"
}

resource "aws_iam_role" "act" {
  name               = data.act_aws_onboarding_parameters.this.role_name
  assume_role_policy = data.act_aws_onboarding_parameters.this.assume_role_policy_json
}

resource "aws_iam_role_policy_attachment" "act" {
  for_each   = toset(data.act_aws_onboarding_parameters.this.managed_policy_arns)
  role       = aws_iam_role.act.name
  policy_arn = each.value
}

resource "aws_iam_role_policy" "act" {
  for_each = data.act_aws_onboarding_parameters.this.custom_policy_documents
  role     = aws_iam_role.act.name
  name     = each.key
  policy   = each.value
}

resource "act_aws_account_deployment" "this" {
  deployment_id           = data.act_aws_onboarding_parameters.this.deployment_id
  account_id              = "111111111111"
  role_arn                = aws_iam_role.act.arn
  external_id_key_version = data.act_aws_onboarding_parameters.this.external_id_key_version
  tags                    = { team = "platform" }

  depends_on = [aws_iam_role_policy_attachment.act, aws_iam_role_policy.act]
}
```

`data.act_aws_onboarding_parameters` is a read and creates nothing. Its `deployment_id`, `role_name` and `external_id` are stable, so a plan you run again shows no change.

## Verification

Act assumes the role, checks the account and checks that the trust policy requires the external ID before it stores anything. A new role can take a minute or two to work everywhere in AWS, so while AWS answers `AccessDenied` the provider asks again, backing off up to 30 seconds between attempts, for up to 2 minutes. A failure that cannot fix itself, such as a trust policy without the external ID, stops after the same answer comes back twice. A failed create stores nothing, so the next apply starts clean.

Use `timeouts` to cap the whole operation; the defaults are 5 minutes for create and update.

On success the apply prints a warning with the deployment's console link. It is not an error: it confirms that Act reached the account.

## When the role breaks

If someone deletes the role or changes its trust policy, the next refresh reports `status = "failed"` with a warning, and the plan updates the deployment in place. Once the configuration has fixed the role, the apply asks Act to verify it again and the deployment is active in the same apply. Set `reverify_on_failure = false` to keep the warning without the extra update.

## External ID

Act derives the external ID from the deployment, so it never changes on its own. A deployment created before derived IDs keeps its stored value with `external_id_source = "legacy"`. Set `external_id_source = "derived"` to move it: Act first checks that the role trusts the derived value, `target_external_id` of the onboarding data source, then switches. Update the trust policy before you apply.

## Destroy

Destroying the resource disconnects the account: Act stops scanning and deletes the credentials it held. The role stays in AWS, and the apply lists it in a warning. With `deletion_protection = true`, a plan that destroys the deployment fails before anything changes. To stop managing the deployment without disconnecting it, use a `removed` block with `lifecycle { destroy = false }` on Terraform 1.7 and later, or `terraform state rm`.

## Schema

### Required

- `account_id` (String) The 12-digit AWS account ID. It must be the account of `role_arn`. Changing it replaces the deployment.
- `deployment_id` (String) The deployment ID Act issued for this target, from `data.act_aws_onboarding_parameters`. Act rejects any other value. Changing it replaces the deployment.
- `role_arn` (String) The ARN of the IAM role Act assumes. Reference the role resource so Terraform creates the role first. Changing it updates the deployment in place and Act verifies the new role.

### Optional

- `allowed_regions` (Set of String) The AWS regions Act scans, such as `us-east-1`. Leave it out to scan every region.
- `deletion_protection` (Boolean) When true, Act refuses to delete the deployment and a plan that destroys it fails. Defaults to `false`.
- `deployment_method` (String) How the role was deployed: `terraform` (default) or `cloudformation`.
- `disabled_capabilities` (Set of String) Act capabilities to turn off for this deployment. The only one today is `eks_cluster_access`.
- `external_id_key_version` (Number) The key version of the external ID, from `data.act_aws_onboarding_parameters`. Passing it pins the external ID the role trusts, so a key rotation between plan and apply cannot change it. It only changes when `external_id_source` moves from `legacy` to `derived`.
- `external_id_source` (String) `derived` for an external ID Act derives from the deployment, or `legacy` for one stored by an older onboarding. Changing `legacy` to `derived` rotates it: Act checks that the role trusts the derived value first. `derived` cannot go back to `legacy`.
- `name` (String) The name Act shows for the deployment, 1 to 64 characters. Act picks one when you leave it out.
- `reverify_on_failure` (Boolean) When the deployment is `failed`, plan a verification so the next apply makes it active again once the role is fixed. Defaults to `true`. Only the provider uses it.
- `tags` (Map of String) Act tags for the deployment, at most 50. They are not AWS tags.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `console_url` (String) The deployment's page in the Act console.
- `created_at` (String) When the deployment was created, in RFC 3339.
- `deployed_version` (String) The role version Act detected.
- `error_code` (String) Why the deployment failed. Null while active.
- `error_message` (String) What Act saw when the deployment failed. Null while active.
- `external_id` (String) The external ID the role's trust policy must require. Not a secret.
- `id` (String) The deployment ID, equal to `deployment_id`.
- `status` (String) `active` when Act can use the role, `failed` when it cannot.
- `update_available` (Boolean) True when the role is older than the version Act recommends.

## Import

Import by the 12-digit account ID or by the deployment ID:

```shell
terraform import act_aws_account_deployment.this 111111111111
```

On Terraform 1.5 and later you can use an `import` block instead. When the onboarding data source returns `existing_deployment`, the account already has a deployment, for example one created in the Act console, and creating another fails with the `import` block to use.

```terraform
import {
  to = act_aws_account_deployment.this
  id = "111111111111"
}
```
