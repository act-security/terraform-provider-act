# act_aws_organization_deployment (Resource)

Connects an AWS organization to Act, either the whole root or a set of organizational units, through an IAM role in the management account or a StackSets delegated administrator account. Act verifies the role and the organization before it stores anything.

## Example Usage

Create the role in the management account, or in a StackSets delegated administrator account, then connect the organization:

```terraform
data "act_aws_onboarding_parameters" "this" {
  organization_id = "o-abcdefghij"
}

resource "aws_iam_role" "act" {
  name               = data.act_aws_onboarding_parameters.this.role_name
  assume_role_policy = data.act_aws_onboarding_parameters.this.assume_role_policy_json
}

resource "aws_iam_role_policy_attachment" "act" {
  for_each   = toset(data.act_aws_onboarding_parameters.this.managed_policy_arns)
  role       = aws_iam_role.act.name
  policy_arn = each.value
}

resource "aws_iam_role_policy" "act" {
  for_each = data.act_aws_onboarding_parameters.this.custom_policy_documents
  role     = aws_iam_role.act.name
  name     = each.key
  policy   = each.value
}

resource "act_aws_organization_deployment" "this" {
  deployment_id           = data.act_aws_onboarding_parameters.this.deployment_id
  organization_id         = "o-abcdefghij"
  root_id                 = "r-ab12"
  excluded_account_ids    = ["333333333333"]
  role_arn                = aws_iam_role.act.arn
  external_id_key_version = data.act_aws_onboarding_parameters.this.external_id_key_version

  depends_on = [aws_iam_role_policy_attachment.act, aws_iam_role_policy.act]
}
```

Member accounts need a role too. Deploy `cloudformation_template_url` from the onboarding data source as a service-managed StackSet to the same root or organizational units. Act reads the accounts from the StackSet, so it never waits for the rollout: use `act_deployment_coverage` to see how far it got.

## Scope

Set `root_id` to cover the whole organization, or `organizational_unit_ids` to cover some units. To leave a unit out, list the others. `excluded_account_ids` leaves single accounts out. Changing the scope updates the deployment in place, and Act verifies it again.

A StackSet accepts at most 850 characters of target IDs. When the units do not fit, the plan fails and suggests `root_id` with `excluded_account_ids`.

## Verification

Act assumes the role, checks that its account belongs to the organization and is the management or delegated administrator account, and checks the external ID, before it stores anything. While AWS answers `AccessDenied` for a new role, the provider asks again for up to 2 minutes. A failure that cannot fix itself stops after the same answer comes back twice, and a failed create stores nothing. Use `timeouts` to cap the operation; the defaults are 5 minutes for create and update.

## Deletion protection

`deletion_protection` defaults to `true` here, so a plan that would destroy the deployment fails before anything changes, and destroying the configuration never removes member roles while the deployment survives. Set `deletion_protection = false` and apply before you destroy it. Destroying it disconnects the organization and lists what still trusts Act in a warning. To stop managing the deployment without disconnecting it, use a `removed` block with `lifecycle { destroy = false }` on Terraform 1.7 and later, or `terraform state rm`.

## Schema

### Required

- `deployment_id` (String) The deployment ID Act issued for this target, from `data.act_aws_onboarding_parameters`. Act rejects any other value. Changing it replaces the deployment.
- `organization_id` (String) The AWS organization ID, `o-` followed by 10 to 32 characters. Act checks that the role's account belongs to it. Changing it replaces the deployment.
- `role_arn` (String) The ARN of the IAM role Act assumes. Reference the role resource so Terraform creates the role first. Changing it updates the deployment in place and Act verifies the new role.

### Optional

- `allowed_regions` (Set of String) The AWS regions Act scans, such as `us-east-1`. Leave it out to scan every region.
- `deletion_protection` (Boolean) When true, Act refuses to delete the deployment and a plan that destroys it fails. Defaults to `true`.
- `deployment_method` (String) How the role was deployed: `terraform` (default) or `cloudformation`.
- `disabled_capabilities` (Set of String) Act capabilities to turn off for this deployment. The only one today is `eks_cluster_access`.
- `excluded_account_ids` (Set of String) Member accounts Act leaves out, as 12-digit IDs.
- `external_id_key_version` (Number) The key version of the external ID, from `data.act_aws_onboarding_parameters`. Passing it pins the external ID the role trusts, so a key rotation between plan and apply cannot change it. It only changes when `external_id_source` moves from `legacy` to `derived`.
- `external_id_source` (String) `derived` for an external ID Act derives from the deployment, or `legacy` for one stored by an older onboarding. Changing `legacy` to `derived` rotates it: Act checks that the role trusts the derived value first. `derived` cannot go back to `legacy`.
- `member_role_name` (String) The name of the role in each member account. Defaults to `ActSecurityRole-<deployment_id>`. Set it when another system, such as Account Factory for Terraform or Control Tower, creates the member roles.
- `member_role_path` (String) The IAM path of the member roles. Defaults to `/`.
- `name` (String) The name Act shows for the deployment, 1 to 64 characters. Act picks one when you leave it out.
- `organizational_unit_ids` (Set of String) The organizational units to cover, `ou-...`. Set this or `root_id`. To leave a sandbox OU out, list the other OUs.
- `reverify_on_failure` (Boolean) When the deployment is `failed`, plan a verification so the next apply makes it active again once the role is fixed. Defaults to `true`. Only the provider uses it.
- `root_id` (String) The organization root ID, `r-...`, to cover every account. Set this or `organizational_unit_ids`. Changing the scope updates the deployment in place and Act verifies it again.
- `tags` (Map of String) Act tags for the deployment, at most 50. They are not AWS tags.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `console_url` (String) The deployment's page in the Act console.
- `created_at` (String) When the deployment was created, in RFC 3339.
- `deployed_version` (String) The role version Act detected.
- `error_code` (String) Why the deployment failed. Null while active.
- `error_message` (String) What Act saw when the deployment failed. Null while active.
- `external_id` (String) The external ID the role's trust policy must require. Not a secret.
- `id` (String) The deployment ID, equal to `deployment_id`.
- `management_account_id` (String) The organization's management account, as AWS reports it.
- `status` (String) `active` when Act can use the role, `failed` when it cannot.
- `update_available` (Boolean) True when the role is older than the version Act recommends.

## Import

Import by the organization ID, the root ID or the deployment ID:

```shell
terraform import act_aws_organization_deployment.this o-abcdefghij
```

On Terraform 1.5 and later you can use an `import` block with the same IDs.
