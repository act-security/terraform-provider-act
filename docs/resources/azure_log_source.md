# act_azure_log_source (Resource)

Collects the tenant-wide Azure activity logs and Entra ID logs of an `act_azure_deployment` through Event Hubs. Act verifies that it can read the Event Hubs before it registers them, so the apply fails and nothing changes when Act cannot use them.

## Example Usage

This continues the `act_azure_deployment` example. The `modules/activity-logs` submodule of the Act module for Azure creates an Event Hub namespace and streams the activity logs of the subscriptions to it; `modules/entra-logs` streams the Entra ID logs to the same namespace. Then the log source tells Act to collect them:

```terraform
module "act_logs" {
  source = "act-security/act/azurerm//modules/activity-logs"

  deployment_id        = act_azure_deployment.this.id
  service_principal_id = act_azure_deployment.this.service_principal_id
  location             = "westeurope"
  subscription_ids     = [var.subscription_id]
}

module "act_entra_logs" {
  source = "act-security/act/azurerm//modules/entra-logs"

  deployment_id         = act_azure_deployment.this.id
  eventhub_namespace_id = module.act_logs.namespace_id
}

resource "act_azure_log_source" "this" {
  deployment_id          = act_azure_deployment.this.id
  events_subscription_id = var.subscription_id
  activity_logs          = true
  entra_id_logs          = true

  depends_on = [module.act_logs, module.act_entra_logs]
}
```

`events_subscription_id` is the subscription that holds the Event Hub namespace, here the one the azurerm provider creates it in. `depends_on` makes Terraform finish the diagnostic settings and the Event Hubs before Act checks them. For a management group, pass `management_group_id` to `modules/activity-logs` instead of `subscription_ids`.

The deployment must be `active`. While it is `pending_consent` or `failed`, Act refuses the log source and the apply fails with the reason; approve Act or fix the deployment, then apply again.

## Streams

Set `activity_logs`, `entra_id_logs` or both to `true`. Each apply sends the whole log source, so setting a stream to `false` stops Act collecting it in place; its Event Hub stays in `event_hubs` with `enabled = false`. To stop collecting both streams, remove the resource.

## Verification

Act checks that it can read the Event Hubs before it registers them. New access to Event Hubs can take several minutes to work everywhere in Azure, so while Act reports that it has not propagated yet, the provider asks again, backing off up to 30 seconds between attempts, for up to 10 minutes. A failure that cannot fix itself stops once the same answer has come back for 30 seconds. Use `timeouts` to cap the whole operation; the defaults are 12 minutes for create and update.

## Reading the log source

Act does not return `events_subscription_id` when it reads the log source, so Terraform keeps the value from your configuration. After an import the state has none, so the first apply updates the log source in place once to send it. When the log source is removed in Act, or collects no stream anymore, the next plan creates it again.

## Destroy

Destroying the resource stops Act collecting the logs. The diagnostic settings and the Event Hub namespace stay in Azure, and the apply lists them in a warning. The modules that created them remove them when you destroy them.

## Schema

### Required

- `deployment_id` (String) The ID of the `act_azure_deployment` that collects the logs. It must be `active`. Changing it replaces the log source.
- `events_subscription_id` (String) The subscription that holds the Event Hub namespace the logs stream to, a lowercase UUID. Changing it updates the log source in place and Act verifies the Event Hubs again. Act does not return it when it is read, so Terraform keeps the value from your configuration: after an import, the first apply sends it once.

### Optional

- `activity_logs` (Boolean) Collect the Azure activity logs. Defaults to `false`. Set it or `entra_id_logs`, or both. Changing it updates the log source in place; setting it to `false` stops collecting the stream.
- `entra_id_logs` (Boolean) Collect the Entra ID sign-in and audit logs. Defaults to `false`. Set it or `activity_logs`, or both. Changing it updates the log source in place; setting it to `false` stops collecting the stream.
