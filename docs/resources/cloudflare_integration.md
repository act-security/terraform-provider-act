# act_cloudflare_integration (Resource)

A Cloudflare integration, connected with a read-only account API token so Act can read your Cloudflare account. One per tenant. The Act console can also connect Cloudflare in one click through a browser sign-in; that has no Terraform equivalent, so use an account API token here.

In Cloudflare, open Manage Account > Account API Tokens and create an account-owned token with the read permissions the Act console lists for Cloudflare. User API tokens and the Global API Key aren't supported. Under Account Resources, select your account, not All accounts. Act checks the connection before it saves anything, so an apply with a token Cloudflare rejects fails and changes nothing.

## Example Usage

```terraform
variable "cloudflare_api_token" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "act_cloudflare_integration" "this" {
  account_id           = "0123456789abcdef0123456789abcdef"
  api_token_wo         = var.cloudflare_api_token
  api_token_wo_version = 1
}
```

The integration `id` stays the same when you rotate the secret or change a setting.

## Secrets

Act never returns the API token. Set it one of two ways, never both:

| Argument | Terraform | Stored in the state |
|---|---|---|
| `api_token_wo` with `api_token_wo_version` | 1.11 and later | No. The value lives only in the configuration, so it can come from an ephemeral variable or an ephemeral resource. |
| `api_token` | 1.5.7 and later | Yes, marked sensitive. Anyone who can read the state can read it. |

To rotate a write-only secret, change the value and increase `api_token_wo_version`. The integration is updated in place. With `api_token`, changing the value is enough.

On Terraform before 1.11, use `api_token` with a sensitive variable:

```terraform
resource "act_cloudflare_integration" "this" {
  account_id = "0123456789abcdef0123456789abcdef"
  api_token  = var.cloudflare_api_token
}
```

Cloudflare account API tokens expire. Before one does, create a new token, put it in the configuration and increase `api_token_wo_version` (or change `api_token`), then delete the old token in Cloudflare.

Changing `account_id` also sends the API token again: Act checks the new settings with the secret you configure and never reuses the stored one for them.

`api_token_updated_at` records when Act last stored a new value. If it moves without Terraform, for example after someone rotates the secret in the Act console, the next plan updates the integration in place and sends the configured value again, with a warning.

## Schema

### Required

- `account_id` (String) The 32-character account ID that follows `dash.cloudflare.com/` in your dashboard URL. Changing it sends the API token again.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `api_token` (String, Sensitive) An account API token, owned by the account rather than a person, with the read permissions the Act console lists for Cloudflare. User API tokens and the Global API Key are not supported. Stored in the Terraform state. Set exactly one of `api_token` and `api_token_wo`; prefer `api_token_wo` on Terraform 1.11 and later.
- `api_token_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) An account API token, owned by the account rather than a person, with the read permissions the Act console lists for Cloudflare. User API tokens and the Global API Key are not supported. Write-only: never stored in the plan or the state. Needs Terraform 1.11 or later. Change `api_token_wo_version` to send a new value.
- `api_token_wo_version` (Number) Any number you choose. Changing it sends `api_token_wo` to Act again, in place.

### Read-Only

- `api_token_updated_at` (String) When Act last stored a new `api_token`, in RFC 3339. When it moves without Terraform, for example after a rotation in the Act console, the next plan sends the configured value again.
- `display_name` (String) The name Act shows for the integration.
- `health_note` (String) What to do about an unhealthy connection. Null while connected.
- `health_reason` (String) Why the connection is unhealthy, when Act reports a reason. Null while connected.
- `id` (String) The installation ID. It stays the same when you rotate `api_token` or change a setting, so notification rules can reference it.
- `status` (String) The connection status: `connected`, `pending`, `error` or `disconnected`.

## Import

Import by integration ID, or by `cloudflare`, since a tenant has at most one Cloudflare integration:

```shell
terraform import act_cloudflare_integration.this cloudflare
```

Import cannot read the secret. Set `api_token` or `api_token_wo` in the configuration; the first apply sends it once.
