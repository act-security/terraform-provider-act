# act_cortex_cloud_integration (Resource)

A Palo Alto Networks Cortex Cloud integration, connected with a Cortex API key so Act can read your assets and issues. One per tenant.

In Cortex Cloud, open Settings > Configurations > Integrations > API Keys and generate a key with the Viewer role, or with a custom role that has View on Public API, Asset Inventory and Cases and Issues. If your tenant uses scope-based access control, scope the key to all assets, all cases and issues and all endpoints. Act checks the connection before it saves anything, so an apply with a key Cortex Cloud rejects fails and changes nothing.

## Example Usage

```terraform
variable "cortex_cloud_api_key" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "act_cortex_cloud_integration" "this" {
  api_url            = "https://api-acme.xdr.us.paloaltonetworks.com"
  api_key_id         = "7"
  security_level     = "standard"
  api_key_wo         = var.cortex_cloud_api_key
  api_key_wo_version = 1
}
```

The integration `id` stays the same when you rotate the secret or change a setting.

## Secrets

Act never returns the API key. Set it one of two ways, never both:

| Argument | Terraform | Stored in the state |
|---|---|---|
| `api_key_wo` with `api_key_wo_version` | 1.11 and later | No. The value lives only in the configuration, so it can come from an ephemeral variable or an ephemeral resource. |
| `api_key` | 1.5.7 and later | Yes, marked sensitive. Anyone who can read the state can read it. |

To rotate a write-only secret, change the value and increase `api_key_wo_version`. The integration is updated in place. With `api_key`, changing the value is enough.

On Terraform before 1.11, use `api_key` with a sensitive variable:

```terraform
resource "act_cortex_cloud_integration" "this" {
  api_url        = "https://api-acme.xdr.us.paloaltonetworks.com"
  api_key_id     = "7"
  security_level = "standard"
  api_key        = var.cortex_cloud_api_key
}
```

Changing `api_url`, `api_key_id` or `security_level` also sends the API key again: Act checks the new settings with the secret you configure and never reuses the stored one for them.

`api_key_updated_at` records when Act last stored a new value. If it moves without Terraform, for example after someone rotates the secret in the Act console, the next plan updates the integration in place and sends the configured value again, with a warning.

## Schema

### Required

- `api_key_id` (String) The number in the ID column of the key on the API Keys page. Changing it sends the API key again.
- `api_url` (String) Your Cortex Cloud API URL, such as `https://api-acme.xdr.us.paloaltonetworks.com`. In Cortex Cloud, open Settings > Configurations > API Keys and select Copy API URL. Changing it sends the API key again.
- `security_level` (String) The security level you chose when you generated the key: `standard` or `advanced`. Changing it sends the API key again.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `api_key` (String, Sensitive) The Cortex Cloud API key, assigned the Viewer role or a custom role with View on Public API, Asset Inventory and Cases and Issues. Stored in the Terraform state. Set exactly one of `api_key` and `api_key_wo`; prefer `api_key_wo` on Terraform 1.11 and later.
- `api_key_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The Cortex Cloud API key, assigned the Viewer role or a custom role with View on Public API, Asset Inventory and Cases and Issues. Write-only: never stored in the plan or the state. Needs Terraform 1.11 or later. Change `api_key_wo_version` to send a new value.
- `api_key_wo_version` (Number) Any number you choose. Changing it sends `api_key_wo` to Act again, in place.

### Read-Only

- `api_key_updated_at` (String) When Act last stored a new `api_key`, in RFC 3339. When it moves without Terraform, for example after a rotation in the Act console, the next plan sends the configured value again.
- `display_name` (String) The name Act shows for the integration.
- `health_note` (String) What to do about an unhealthy connection. Null while connected.
- `health_reason` (String) Why the connection is unhealthy, when Act reports a reason. Null while connected.
- `id` (String) The installation ID. It stays the same when you rotate `api_key` or change a setting, so notification rules can reference it.
- `status` (String) The connection status: `connected`, `pending`, `error` or `disconnected`.

## Import

Import by integration ID, or by `cortex-cloud`, since a tenant has at most one Cortex Cloud integration:

```shell
terraform import act_cortex_cloud_integration.this cortex-cloud
```

Import cannot read the secret. Set `api_key` or `api_key_wo` in the configuration; the first apply sends it once.
