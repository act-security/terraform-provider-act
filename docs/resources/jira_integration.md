# act_jira_integration (Resource)

A Jira Cloud integration, connected with a scoped Atlassian API token. Act creates and tracks Jira issues for its findings. One per tenant.

Create a scoped Atlassian API token for Jira with `read:jira-work`, `write:jira-work` and `read:jira-user`. Only Jira Cloud sites are supported. Act checks the connection before it saves anything, so an apply with credentials Jira rejects fails and changes nothing.

## Example Usage

```terraform
variable "jira_api_token" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "act_jira_integration" "this" {
  base_url             = "https://acme.atlassian.net"
  email                = "act-bot@acme.com"
  api_token_wo         = var.jira_api_token
  api_token_wo_version = 1
}
```

Reference the integration from a notification rule with its `id`. The ID stays the same when you rotate the secret or change a setting.

## Secrets

Act never returns the API token. Set it one of two ways, never both:

| Argument | Terraform | Stored in the state |
|---|---|---|
| `api_token_wo` with `api_token_wo_version` | 1.11 and later | No. The value lives only in the configuration, so it can come from an ephemeral variable or an ephemeral resource. |
| `api_token` | 1.5.7 and later | Yes, marked sensitive. Anyone who can read the state can read it. |

To rotate a write-only secret, change the value and increase `api_token_wo_version`. The integration is updated in place. With `api_token`, changing the value is enough.

On Terraform before 1.11, use `api_token` with a sensitive variable:

```terraform
resource "act_jira_integration" "this" {
  base_url  = "https://acme.atlassian.net"
  email     = "act-bot@acme.com"
  api_token = var.jira_api_token
}
```

Changing `base_url` or `email` also sends the API token again: Act checks the new settings with the secret you configure and never reuses the stored one for them.

`api_token_updated_at` records when Act last stored a new value. If it moves without Terraform, for example after someone rotates the secret in the Act console, the next plan updates the integration in place and sends the configured value again, with a warning.

## Schema

### Required

- `base_url` (String) Your Atlassian site URL, such as `https://acme.atlassian.net`. Changing it sends the API token again.
- `email` (String) The email address of the Atlassian account that created the token. Changing it sends the API token again.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `api_token` (String, Sensitive) A scoped Atlassian API token with `read:jira-work`, `write:jira-work` and `read:jira-user`. Stored in the Terraform state. Set exactly one of `api_token` and `api_token_wo`; prefer `api_token_wo` on Terraform 1.11 and later.
- `api_token_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) A scoped Atlassian API token with `read:jira-work`, `write:jira-work` and `read:jira-user`. Write-only: never stored in the plan or the state. Needs Terraform 1.11 or later. Change `api_token_wo_version` to send a new value.
- `api_token_wo_version` (Number) Any number you choose. Changing it sends `api_token_wo` to Act again, in place.

### Read-Only

- `api_token_updated_at` (String) When Act last stored a new `api_token`, in RFC 3339. When it moves without Terraform, for example after a rotation in the Act console, the next plan sends the configured value again.
- `display_name` (String) The name Act shows for the integration.
- `health_note` (String) What to do about an unhealthy connection. Null while connected.
- `health_reason` (String) Why the connection is unhealthy, when Act reports a reason. Null while connected.
- `id` (String) The installation ID. It stays the same when you rotate `api_token` or change a setting, so notification rules can reference it.
- `status` (String) The connection status: `connected`, `pending`, `error` or `disconnected`.

## Import

Import by integration ID, or by `jira`, since a tenant has at most one Jira integration:

```shell
terraform import act_jira_integration.this jira
```

Import cannot read the secret. Set `api_token` or `api_token_wo` in the configuration; the first apply sends it once.
