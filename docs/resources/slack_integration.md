# act_slack_integration (Resource)

A Slack integration, connected with the bot token of a Slack app you create from the Act manifest. Act sends notifications to the channels a notification rule names. One per tenant.

The Slack app must already exist in your workspace. Create it from the manifest shown in **Settings → Integrations → Slack** in the Act console, install it, and copy its Bot User OAuth Token. Act checks the connection before it saves anything, so an apply with credentials Slack rejects fails and changes nothing.

## Example Usage

```terraform
variable "slack_bot_token" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "act_slack_integration" "this" {
  bot_token_wo         = var.slack_bot_token
  bot_token_wo_version = 1
}
```

Reference the integration from a notification rule with its `id`. The ID stays the same when you rotate the secret or change a setting.

## Secrets

Act never returns the bot token. Set it one of two ways, never both:

| Argument | Terraform | Stored in the state |
|---|---|---|
| `bot_token_wo` with `bot_token_wo_version` | 1.11 and later | No. The value lives only in the configuration, so it can come from an ephemeral variable or an ephemeral resource. |
| `bot_token` | 1.5.7 and later | Yes, marked sensitive. Anyone who can read the state can read it. |

To rotate a write-only secret, change the value and increase `bot_token_wo_version`. The integration is updated in place. With `bot_token`, changing the value is enough.

On Terraform before 1.11, use `bot_token` with a sensitive variable:

```terraform
resource "act_slack_integration" "this" {
  bot_token = var.slack_bot_token
}
```


`bot_token_updated_at` records when Act last stored a new value. If it moves without Terraform, for example after someone rotates the secret in the Act console, the next plan updates the integration in place and sends the configured value again, with a warning.

## Schema

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `bot_token` (String, Sensitive) The app's Bot User OAuth Token, starting with `xoxb-`. Stored in the Terraform state. Set exactly one of `bot_token` and `bot_token_wo`; prefer `bot_token_wo` on Terraform 1.11 and later.
- `bot_token_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The app's Bot User OAuth Token, starting with `xoxb-`. Write-only: never stored in the plan or the state. Needs Terraform 1.11 or later. Change `bot_token_wo_version` to send a new value.
- `bot_token_wo_version` (Number) Any number you choose. Changing it sends `bot_token_wo` to Act again, in place.

### Read-Only

- `bot_token_updated_at` (String) When Act last stored a new `bot_token`, in RFC 3339. When it moves without Terraform, for example after a rotation in the Act console, the next plan sends the configured value again.
- `display_name` (String) The name Act shows for the integration.
- `health_note` (String) What to do about an unhealthy connection. Null while connected.
- `health_reason` (String) Why the connection is unhealthy, when Act reports a reason. Null while connected.
- `id` (String) The installation ID. It stays the same when you rotate `bot_token` or change a setting, so notification rules can reference it.
- `status` (String) The connection status: `connected`, `pending`, `error` or `disconnected`.

## Import

Import by integration ID, or by `slack`, since a tenant has at most one Slack integration:

```shell
terraform import act_slack_integration.this slack
```

Import cannot read the secret. Set `bot_token` or `bot_token_wo` in the configuration; the first apply sends it once.
